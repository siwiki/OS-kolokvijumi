schedule
Implementirati operacije `get` i `put` klase `Scheduler` koja podržava CFS algoritam raspoređivanja procesa. Drugi parametar operacije `put` daje izmereno realno vreme koje je dati proces koristio procesor poslednji put, počev od trenutka kad mu je dat procesor, dok taj procesor nije izgubio. Ako ovaj parametar ima vrednost 0, proces stiže u red spremnih iz stanja suspenzije. Tip `Time` je dovoljno velik tip neoznačenih celih brojeva i predstavlja vremenski interval. Na raspolaganju je i statička operacija `Timing::getTime` koja vraća vrednost tipa `Time`, kao interval realnog vremena koje je proteklo od početka rada procesora. Operacije klase `PCB`, koja apstrahuje proces, imaju sledeće značenje:

- `get/setExecTime`: vraća/postavlja atribut procesa u kom se čuva ukupno vreme izvršavanja (*execution time*) počev od trenutka kad je proces postao spreman u tekućem naletu izvršavanja;
- `get/setEntranceTime`: vraća/postavlja atribut procesa u kom se čuva trenutak u kom je proces stigao u red spremnih u tekućem naletu izvršavanja;
- `setTimeSlice`: postavlja atribut procesa u kom se zadaje dužina vremenskog odsečka kojim se ograničava korišćenje procesora; ovaj atribut treba da bude postavljen na odgovarajuću vrednost kada dati proces bude izabran u operaciji `Scheduler::get`.

Na raspolaganju je i klasa `RBTree` koja implementira crveno-crno stablo kao red spremnih procesa unutar objekta klase `Scheduler`. Operacija `RBTree::getSize` vraća broj procesa u tom redu. Stablo sortira procese po vrednosti atributa `getExecTime` procesa.
```cpp
class PCB {
public:
    Time getExecTime() const;
    void setExecTime(Time time);

    Time getEntranceTime() const;
    void setEntranceTime(Time time);

    void setTimeslice(Time time);
    ...
};

class RBTree {
public:
    RBTree();
    void put(PCB*);
    PCB* get();
    unsigned long getSize() const;
    ...
};

class Scheduler {
public:
    Scheduler() {}
    PCB* get();
    void put(PCB*, Time execTime=0);

private:
    RBTree queue;
};
```

sharedobj
U nekom složenom sistemu napravljenom na jeziku C++ u upotrebi su dva monitora čiji je zapis dat dole. Značenje klase `Mutex` je kao što je objašnjeno na predavanjima. `Monitor1` se, osim unutar operacija klase `Monitor2`, koristi i iz drugih delova sistema, tj. drugi delovi sistema pozivaju njegovu operaciju `op1`. Međutim, zbog specifičnosti značenja ovih klasa i njihovih operacija, kao i struktura podataka do kojih se isključuje uporedan pristup, nije potrebno da se to međusobno isključenje operacije `Monitor1::op1` radi kada se ona poziva iz operacije `Monitor2::op2`, već samo onda kada se ona poziva iz drugih delova ovog sistema. Potrebno je preurediti ove dve klase na jednostavan način tako da ovo bude zadovoljeno, a da drugi delovi ovog sistema ne moraju da se menjaju uopšte.
```cpp
class Monitor1 {
public:
    Monitor1() : mySem(1) {}
    void op1(T t);
private:
    Semaphore mySem;
};

void Monitor1::op1(T t) {
    Mutex dummy(&mySem);
    ...
}

class Monitor2 {
public:
    Monitor2(Monitor1* m1) : mySem(1), myM1(m1) {}
    void op2(T t);
private:
    Semaphore mySem;
    Monitor1* myM1;
};

void Monitor2::op2(T t) {
    Mutex dummy(&mySem);
    ...
    myM1->op1(t);
    ...
}
```

network
Napisati kod servera koji omogućava slanje poruka između dva korisnika. Korisnik se prijavljuje serveru i tom prilikom mu dostavlja svoje korisničko ime. Nakon prijavljivanja može da koristi server. Korisnik može da pošalje poruku bilo kom prijavljenom korisniku. Poruka ne može sadržati znakove `#` i prelazak u novi red. U slučaju da nema trenutno prijavljenog korisnika za kojeg je stigla poruka, server treba samo da je ignoriše. Server treba da ima mogućnost obrade zahteva od više klijenata uporedo. Server osluškuje na portu 5555.
